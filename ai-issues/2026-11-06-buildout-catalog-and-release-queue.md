# iLoveWordSearch — complete candidate catalog, build order and release inventory
Prepared 2026-11-06 · Companion to MASTER-BUILDOUT-AND-CONTROLLED-RELEASES.md

**Purpose:** a finite, explicit implementation queue for building immediately, WITHOUT equating build completion with publication. This catalog is a product/editorial research backlog, not a mandate to publish every suggestion. Existing published pages are deliberately kept separate from proposals. New URL paths are reserved only after an actual collision and canonical-intent check against the live source/sitemap.

## How to read the queue

- Priority **A** = supported by own search/usage data or an urgent seasonal delivery need. **B** = plausible user value and feasible with existing generator but weaker current demand. **C** = longer-term speculative idea. **NO** = reject as presently framed. These are prioritization labels, not estimated SEO traffic.
- Action **BUILD NOW** = implement/create the reviewed draft asset on a review branch now, irrespective of release date. **RESEARCH NOW** = inspect real feasibility now and build only if it passes. **DEFER** = park implementation until named evidence/dependency exists. **REUSE** = existing published URL/feature should be improved or connected, not cloned.
- Status **EXISTING PUBLISHED / EXISTING DRAFT / PROPOSAL / NOT READY / READY / PUBLISHED** must be retained for each concrete item in the machine-readable manifest. Proposed strings below are working titles, NOT approved URLs, keywords, or assured page counts.
- Each line is a candidate puzzle, collection, pack, guide, tool, or product capability. A word-search *pack* might contain 5–10 independently reviewed puzzles but still use **one** indexable browse URL. Releasing extra combinations, filters, PDF variants and answer views does not justify more indexable URLs.
- Build batches can overlap; use isolation for shared code. Assign exact WPs/PRs once baseline W46 integration is clear.

## H. Publication selection algorithm, with no fabricated thresholds

1. Select from READY inventory, not brainstorms. Validated content only.
2. Eliminate exact/near duplicate purpose, thin hubs, same seed/words, poor worksheet output and copyright/cultural factual risk. Canonicalize variants under existing pages.
3. Consider seasonal deadlines, plus real GSC/Bing impressions/queries, current category CTR and long-run diversification. Seasonal candidate may be prioritized without current keyword volume, but must be labeled a hypothesis.
4. Prefer proven format behavior: hard/printable/PDF/answers, then large-print/teacher use. Make 1–3 genuinely new indexable URL selections for initial weekly review **only if they pass**; usually fewer. This is a review throttle, NOT an SEO algorithm rule.
5. Separate generic utility deploys from content publications. There is no need to hold cosmetic UI until next Friday; no need to publish new SEO content because a tool shipped.
6. Assess 7/14/28/56/90 day age cohorts without conflating indexed status, impressions and clicks or comparing seasonal peaks to off-season. Report total organic **and** excluding hard-printable collection.
7. Stop adding to a cluster if new content cannibalizes stronger canonicals, is not indexed after a fair period, has thin supporting material, or fails to solve a distinct user problem. Improve existing pages rather than mass-generate replacements.
8. Increase publication only when incremental human benefit and stable site quality is demonstrated. There is no promised growth rate, indexation date, page-count target or revenue forecast.

## I. Do-not-build / no-go items (without new evidence)

- NO: 500–5,000 generated topic pages from generic placeholder words or unreviewed AI lists.
- NO: a separate indexable URL for every answer key, size toggle, difficulty toggle, PDF/print/mobile variant or year suffix.
- NO: mass SEO title/H1 rewrites of the 150 published puzzles, or replacing the successful hard collection URL.
- NO: generic “all grades × all subjects” keyword permutations with identical layouts and filler text.
- NO: putting drafts in sitemap, links or indexable public exports merely because their code exists.
- NO: fabricated factual history/geography/science, proprietary film character puzzles or noncommercial datasets presented as free.
- NO: medically suggestive “brain training prevents dementia” claims or unsupported ASL/Braille accessibility assertions.
- NO: protected advertising placeholder or ad layout changes under general SEO, UX or audit-test authority.
- NO: speculative paid accounts/collaborative backends before product, security, usage and cost evidence.
- NO: forced keyword-density/count, unverifiable ranking/SEO promises or pretending low content cadence guarantees safety.
- NO: large cross-site self-promotion blocks or network-wide irrelevant backlinks.
