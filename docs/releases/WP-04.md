# WP-04 — Static share and release regression coverage

Status: test coverage implemented; independent review pending. Branch `release/2026-W46-regression-coverage` starts from PR #2 at `c6539992f95ea584498329bc319ac38edbbe160e`. The containing commit and draft PR identify this checkpoint. No production deployment or merge.

## Change and evidence

- `tests/e2e/share-route-parity.mjs` follows a real encoded seeded definition through all six exported utility paths, via the committed rewrite rules as interpreted by the existing static-export server. It compares all 144 grid tokens across play, print, PDF route, answer key, embed and custom; compares exact answer line endpoints against revealed play answers; extracts every grid row from the downloaded real PDF; compares the generated QR PNG across print, PDF and answer routes; checks invalid state generates no fallback on all six; and checks utility robots meta, response headers and canonical protection plus the generator's canonical.
- `tests/e2e/static-export-server.mjs` now evaluates headers against the requested path while still resolving the file from the rewritten path. The new check exposed that the simulator previously applied headers to `/play.html` instead of `/play/<state>`, missing the matching `/play/*` rule. This is a local test harness correction, not a change to production Netlify configuration or proof of Netlify's actual header behavior.
- Node 22 `npm ci`, `npm run lint`, `npm run typecheck`, `npm test` (131 tests, including unchanged 150-puzzle fingerprint snapshots), `npm run audit:content`, `npm run build`, and `npm run audit:static-host` passed. Static audit reports 217 sitemap pages and 35 redirects. There is no formatter script; `git diff --check` is the whitespace check. `npm ci` reported 20 existing advisories (7 moderate, 10 high, 3 critical).
- Against the built export on port 3222: `node tests/e2e/share-route-parity.mjs`, `npm run test:preview`, and `npm run audit:pdf` passed. The PDF audit validated two A4 landscape pages, title and word content, answer page and embedded QR images. The parity test compares the QR image across utility routes; it does not decode the image or certify a scan.
- Running the same parity test against the separate WP-01 server on port 3201 passed the puzzle, PDF, answers, QR image, invalid-state and metadata assertions but failed all six X-Robots-Tag assertions because that server uses the original simulator. Repeat after integrating the harness change. WP-01 input compatibility remains a separate review and integration gate.

## Boundaries and next work

The local server is a partial simulation using `out/_redirects` and `out/_headers`; it does not certify Netlify rewrite/header semantics, DNS, HTTPS, caching, physical printing or real-device QR scanning. Test those on the approved provider preview and devices. The existing baseline route audit (212 reported issues), Lighthouse best-practices score 77, and dependency advisories remain open release gates; this change does not alter ads or production metadata. The deterministic test fixture samples one configuration and supplements, rather than replaces, the existing fingerprint and PDF suites. No snapshot was regenerated.

Additional checks: `npm run test:a11y` passed 14 archetypes at mobile and desktop, including axe, zoom, skip-link and reduced-motion checks. `npm run test:preview` passed eight responsive viewports. The test harness was also rechecked with `npm run lint`, `npm run typecheck`, `npm run audit:static-host`, and `git diff --check` after modification.

`BASE_URL=http://127.0.0.1:3220 npm run test:e2e` passed direction validation, browser smoke (53 routes × 9 viewports, utility and solver workflows), and the existing monetization placeholder checks. This full run used the pre-correction server process; the focused parity and accessibility/preview checks used the corrected simulator on port 3222. No ad behavior was changed.
