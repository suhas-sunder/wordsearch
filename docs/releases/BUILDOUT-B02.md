## Reusable audit

`npm run audit:candidates -- <file.json> --export` reads a regular JSON file capped at 256,000 bytes, containing 1–20 strict typed staged-puzzle objects. Invalid input produces structured schema issues before generation; `--export-dir=<directory>` inspects another built static export. It reports structured schema, collision, placement, exposure and PDF findings, and exits nonzero if any are present. Input must be trusted local editorial data, not a public upload endpoint. Existing draft puzzles and 35 redirect sources are included in collision checks. It checks the expected `/word-searches/<category>/<slug>` route and maps its segment to a published primary category; that mechanical mapping does not decide semantic suitability. It catches normalized token-set duplicates and 80%-overlap candidates using the generator alphabet pack, including spacing and case variations; semantic intent still needs a human.

The audit uses the central parser and generator, flags unsupported plain-Latin input, parser loss, normalized duplicate/token-equivalent answers, excluded entries, direction/difficulty inconsistencies and invalid or unsafe dimensions/workloads. It freezes SHA-256 hashes of the full generated request, grid, and ordered answer placements. It then generates real portrait Letter and A4 two-page PDFs, extracts and compares the grids, verifies every answer line endpoint against the frozen cells, checks the expected labels and paper bounds, and records measured grid and word-bank font sizes. Grid under 8 pt or word bank under 9 pt prompts review; these are internal screening floors, not accessibility standards or proof of legibility. QR-disabled PDFs are tested; browser print, QR/share replay, other orientations, physical printers, visual overlap, and assistive technology require separate human review. A valid source URL does not establish factual truth, licensing or approval.

With `--export`, the audit checks candidate paths against the route registry, sitemap, search catalog, built HTML files, generated sitemap and search index, and links/references in indexed HTML. It does not register or publish candidates and does not treat historical noindex drafts as source-only. Exact path scanning cannot prove absence of every indirect representation or metadata leak; release review remains required. Factual, licensing, age suitability, placement meaning, genuine difficulty, canonical intent and editorial signoff remain human gates. All candidates remain drafts regardless of technical results.
