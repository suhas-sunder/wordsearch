## Deterministic safeguard and compatibility

Before any grid allocation or placement, validation parses/deduplicates the
effective word list, uses the centralized **unchanged** size calculation, and
estimates an upper bound on token comparisons:

`sum(max(300, rows * cols * directionEntries) * word.tokens.length)`

Words longer than the grid's maximum dimension are skipped by the existing
algorithm and contribute zero. Reject bounds above **16,000,000** with an explicit
workload message. Exact-bound inputs are accepted. This bounds attempts and token
checks independently of early collisions or seed luck. It does not use wall-clock
cutoffs, truncate words, deduplicate directions, reduce retries, or return partial
new grids. Direction order and repetitions still influence accepted puzzles
exactly as before. Sizing moved to one shared helper without changing its formula.

Builder validation, share-state admission and generator validation use the same
gate. Invalid external builder state shows the explicit recovery shell; invalid
utility state shows the existing invalid-link shell and no puzzle/export.
Edited invalid state retains controls and blocks stale output until recovery.

Five focused unit tests cover the exact bound, next-word rejection, overlap modes,
auto-size, omitted hard presets, deduplicated words, too-long skipped words and
admitted 128-entry replay. Existing compatibility tests still verify the complete
pre-change nine-repeated-E fingerprint, every one of the 150 published puzzle
fingerprints and the three preset fingerprints (including grids, placements,
answer cells and URLs). No snapshots were regenerated with new values.

Known valid historical fixtures remain unchanged; universal compatibility with
previously unchecked arbitrary links is not claimed. Some formerly accepted
extreme configurations, including the eight-direction dense fixture despite its
fast observed seed, are deliberately rejected because their worst-case bound
exceeds the limit. Review this restriction as part of PR #9's release gate.
The bound limits placement work; it does not promise a universal latency target
or certify every browser/device. Physical mobile devices remain untested.

## Harness corrections

An attempted static-server restart failed because listener discovery returned no
listener despite an active server. Initial post-build parity timed out on mixed
cached/new assets; the affected run was stopped and excluded. The known server
process was then stopped, a fresh server started, and all affected checks rerun.
The first new benchmark assertion matched Next's route announcer as a second
alert; it was scoped to the builder error. An added admitted fixture initially
used 128 rather than 12 repeated directions (above the stated limit); that harness
attempt was stopped, corrected and the complete 32-navigation benchmark passed.
These corrections changed no production assertions, timeout values or ad behavior.
