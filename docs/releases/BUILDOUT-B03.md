## Scope and contract

Source-only `createPuzzlePackPdf` composes the existing PDF renderer's student and answer pages. A named, caller-owned slug ID and ordered unique entry IDs identify a set; IDs are not persisted, registered, or intrinsically bound to a revision. The caller must version a changed set. The engine accepts exactly 5 or 10 distinct seeded grids, 20×20 maximum, 30 placed words maximum and 2,000 characters of word input per puzzle. It validates the PDF data, replays each request through the central generator, rejects duplicates, unsupported input warnings, excluded words and mismatched grids/placements before composing any output, and requires exactly two source pages. Output is Letter or A4 portrait, one sheet per puzzle and answer, in interleaved or answers-last order. Share targets are derived from each request. No QR, ads, page route, saved presets, content, navigation or user interface is introduced.

Output uses the current renderer's ink-saving setting: it is not strictly monochrome because some existing text and rules use tinted grays. Contrast, unusually long titles/word banks, and unusually dense puzzles require case-specific print review; this engine does not certify layout fit or large-print legibility for all accepted input. One-, two- or four-up layouts, browser print controls, persistence, curated content, a user-facing builder, and strict black/white remain future milestones. Existing renderer font limitations apply; unsupported glyphs fail rather than being silently changed. The share URL footer in the existing renderer is truncated for long URLs. Browser export uses an object URL; no API or ad is involved.
